# SignalScape: Implementation Checkpoints

Tracks build progress by week. Course milestones: proposal (week 1), design (week 2), MVP (weeks 3 to 4), feature-complete and deployed (weeks 5 to 6), testing and docs (week 7), defense (week 8). Missing a milestone costs points. See `REQUIREMENTS.md` for what each item means. Tick items as they're done.

**Repo layout**
- `api/`: REST API, database migrations, interpolation and access point estimation, Docker setup.
- `app/`: Flutter Android app.

**Status (Nov 16, 2026):** M3, M4, M5, M6 and M7 are done (3D view, 2D map, survey summary and export, history, profile and settings, admin users, delete buildings and floors; phone test, docs, coverage, privacy checks, accuracy check, two-floor survey and the IEEE paper draft). A scheduled database backup is out of scope (Boon decided 2026-11-16); the runbook still has recommended manual dump and restore commands. The repo is tagged `v1.0` on the merge of PR #30. Week dates are set once week 1's start is confirmed.

## M9: Access point placement — due 19 Nov 2026 (FR-23, FR-24, FR-25, NFR-5)

First slice, with M10. This is the estimated access point markers, not the walk trail.

- [x] Replace `estimate_access_points()` in `api/app/services/processing.py`. Stop using the power-weighted centroid of the 10 strongest readings (`AP_TOP_READINGS`, `10^(rssi/10)`, method `weighted_centroid`). Use a log-distance path-loss range plus a best-fit (trilateration) position, so a marker can sit beyond the walked path (FR-23, NFR-5). Keep storing `method`.
- [x] Require at least 5 readings spread over 3 m or more for a confident placement. Below that, show the marker faded with a "low confidence" flag; do not hide it (FR-24). Keep 5 and 3 m as named settings, not magic numbers scattered in the UI.
- [x] Colour access point markers by placement confidence on the 2D map (`app/lib/screens/map_screen.dart`, today `AppColors.primary` for every marker) and in the 3D viewer (`api/app/static/viewer/viewer.mjs`, today a single `AP_COLOR`). The tap/detail text shows confidence, reading count and spread, not only `max_rssi_dbm` (FR-25).
- [x] Unit tests for the new math, run in CI: a case where the true position is outside the walked points, and a tight cluster that must show as low confidence.
- [ ] Follow-up only, not this milestone's main work and not part of the 19 Nov slice: if placements still collapse because almost every reading sits on the start point, run a short instrumented walk that logs step count against readings (`app/lib/core/dead_reckoning.dart`, 0.7 m/step, fixed 1.1 m/s² threshold).
